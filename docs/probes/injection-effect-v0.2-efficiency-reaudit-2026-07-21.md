## 修正后的判读

1. **此前把 Django 主比较概括成“resolved 2:2，未观察到提升”是不完整的。** 冻结预注册明确规定：A-L 相比 B，resolved 多至少 1 题**或升级阶梯少至少 30%**，即方向支持 H1。实际阶梯为 `3 vs 6`，A-L 少 **50%**，所以 Django 族按预注册规则已经给出 H1 的方向性支持；准确说法应是“resolved 无差异，但预注册的过程指标有方向信号”。
2. **新增效率维度没有给 A-L 一个整齐的全面胜利，但也绝不是纯 null。** A-L 相比 B 聚合轮次少 6.7%、agent 时长少 10.3%、等价成本少 2.6%；producer 时长反而多 2.5%。分题看，第 2 题轮次少 30.4%、成本少 24.3%，第 3 题却轮次多 18.2%、成本多 27.6%，方向不一致。
3. **A-K 当前不能靠“更便宜”翻案。** 第 3 题的低轮次/低成本来自 unresolved 空 patch。只看双方都 resolved 的第 2 题，A-K 相比 B 轮次多 8.7%、agent 时长多 7.8%、成本多 9.7%，且阶梯同为 4。
4. **C 有一个值得保留的效率信号，但样本只有一题。** C 第 3 题首次实际注入 2 条 resident lessons，相比 B 同题轮次少 31.8%、agent 时长少 37.7%、成本少 39.9%，两者都 resolved；但 C 第 2 题实际为空注入且更慢/更贵。C 聚合成本没有高于 A-L，故本族不支持 H2 的“C 更贵”部分。
5. **单次轨迹噪声很大。** 无历史注入的第 1 题，四臂轮次已从 16 到 63、agent 时长从 128.249s 到 955.402s、等价成本从 ¥0.532196 到 ¥6.449616，且 C 未 resolved。温度为 0 不等于端到端完全确定；在每格仅一次运行时，效率差不能直接写成稳定因果效应。

因此，v0.2 当前最准确的状态不是“knack/lesson 没有效果”，也不是“效率翻案已成立”，而是：**Django 的 resolved 主比较打平；A-L 已按预注册的阶梯规则获得方向性支持；额外效率 readout 呈题目异质性；A-K 未见收益；C 第 3 题有单点效率信号；SymPy 未跑，整体结论仍未完成。**
