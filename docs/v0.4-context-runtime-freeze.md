  # v0.4 Context Runtime Freeze

## 1. Scope

v0.4 freezes the Context Runtime trunk: the path that turns the active task state, pinned memory, retrieved memory, and bounded diagnostics into the L1 prompt context used by the agent.

This freeze covers deterministic runtime assembly, recall, observability, and integration evals. It does not freeze or include:

- Turn Intake LLM automatic extraction.
- Doc Findings write flow.
- Artifact Store.
- Semble Code RAG integration.
- Real eval runner `events.jsonl` ingestion.

The frozen scope is intentionally narrower than the full roadmap. The goal is to preserve the runtime invariants that keep L1 prompt construction inspectable, bounded, and reproducible.

## 3. Runtime Data Flow

The v0.4 L1 prompt is assembled from the current task state and retrieved memory:

```text
Current user message
+ recent raw turns
+ pinned context:
  - TaskSpec
  - WorkingMemory
  - TaskLedger
+ RecallRouter retrieved context:
  - Strategy Genes
  - Preferences
  - Doc Findings
  - Historical WorkingMemorySnapshots
  - Artifact refs
+ ContextBuilder
= L1 Prompt
```

Important boundaries:

- L1 is rebuilt every turn from stores and current inputs.
- L2 does not go through RAG. WorkingMemory and TaskLedger are pinned context.
- TaskLedger is pinned context, not retrieved context.
- L3/L0 memory enters through RecallRouter.
- Historical WorkingMemorySnapshots are compact summaries with evidence pointers.
- A summary does not replace `evidenceRefs`, `events.jsonl`, or `outcome.json`.

## 4. Invariants

1. L1 must not inherit the previous turn's prompt.
2. ContextBuilder must not perform retrieval; it only consumes pinned context plus `RecallBundle`.
3. RecallRouter must not recall the current task/run's WorkingMemorySnapshot.
4. TaskLedger rejections must not be physically deleted.
5. Hard rejection can only come from user correction or explicit source.
6. Removed rejection must not render and must not participate in recall score penalties.
7. Recall ranking must use `score.total`.
8. Legacy score fields (`score.trigger`, `score.keyword`, `score.metadata`, `score.vector`) are compatibility fields only.
9. `/context` must be read-only and must not write memory.
10. Trace Grader must read `events.jsonl` only and must not mutate run archive state.

## 5. Eval Coverage

### Trace Grader Tests

- `tier-selection.eval.test.ts`: covers L1 tier selection, heavy trigger precedence, non-minimal write/open-question paths, user corrections, lostness, eval failure analysis, harness modification, recent errors, and tool thrashing.
- `recall-ranking.eval.test.ts`: covers score bounds, stable ranking, heavy-tier relevance/evidence weighting, recency-only demotion, TaskLedger rejection penalties, and legacy score compatibility fields.
- `task-ledger-safety.eval.test.ts`: covers TaskLedger rendering, hard/soft rejection labels, `DO NOT revisit`, removed rejection filtering, resolved question filtering, and active rejection penalties.
- `context-rebuild-invariant.eval.test.ts`: covers rebuilding L1 from current inputs rather than inheriting prior prompt content.
- `wm-snapshot-run-archive.eval.test.ts`: covers WorkingMemorySnapshot persistence, summary/evidence pointer shape, historical snapshot recall, and current task/run exclusion.
- `context-inspector.eval.test.ts`: covers safe empty results, active task counts, ledger counts, recall counts, top item dimensions, diagnostics, and stable formatter sections.
- `trace-grader-smoke.eval.test.ts`: covers the v0.4 anti-cheating smoke guard with success-only, read-only, and write-plus-validation traces.

## 6. Known Limitations

- Trace Grader v0 checks tool calls, write signals, validation commands, and fake success claims, but it does not judge semantic task quality.
- The eval runner does not yet automatically ingest real `events.jsonl` artifacts.
- Turn Intake is not implemented; TaskLedger currently needs explicit writes.
- Doc Findings have type and recall support, but no formal write flow.
- Artifact Store and drill-down channel are not complete.
- Semble is a future Code RAG integration point and is not a v0.4 blocker.
