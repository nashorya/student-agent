# v0.4 Context Runtime Freeze

## 1. Scope

v0.4 冻结的是 Context Runtime 主干：也就是把当前活跃任务状态、pinned memory、retrieved memory 和受控诊断信息组装成 agent 使用的 L1 prompt context 的路径。

本次 freeze 覆盖确定性的 runtime assembly、recall、可观测性与 integration eval。不包含：

- Turn Intake LLM 自动抽取。
- Doc Findings 写入流程。
- Artifact Store。
- Semble Code RAG 集成。
- 真实 eval runner 的 `events.jsonl` 自动接入。

这个冻结范围有意小于完整 roadmap。目标是保护 L1 prompt 构建过程中的核心不变量，让它保持可检查、可预算、可复现。

## 3. Runtime Data Flow

v0.4 L1 prompt 由当前 task state 与 retrieved memory 组装：

```text
Current user message
+ recent raw turns
+ pinned context:
  - TaskSpec
  - WorkingMemory
  - TaskLedger
+ RecallRouter retrieved context:
  - Strategy Genes
  - Preferences
  - Doc Findings
  - Historical WorkingMemorySnapshots
  - Artifact refs
+ ContextBuilder
= L1 Prompt
```

关键边界：

- L1 每一轮都从 stores 和当前输入重新构建。
- L2 不走 RAG。WorkingMemory 和 TaskLedger 是 pinned context。
- TaskLedger 是 pinned context，不是 retrieved context。
- L3/L0 memory 通过 RecallRouter 进入上下文。
- Historical WorkingMemorySnapshots 是紧凑 summary 加 evidence pointers。
- Summary 不替代 `evidenceRefs`、`events.jsonl` 或 `outcome.json`。

## 4. Invariants

1. L1 不得继承上一轮 prompt。
2. ContextBuilder 不得执行检索；它只消费 pinned context 和 `RecallBundle`。
3. RecallRouter 不得召回当前 task/run 的 WorkingMemorySnapshot。
4. TaskLedger rejections 不得物理删除。
5. Hard rejection 只能来自用户纠正或 explicit source。
6. Removed rejection 不得渲染，也不得参与 recall score penalty。
7. Recall ranking 必须使用 `score.total`。
8. 旧 score 字段（`score.trigger`、`score.keyword`、`score.metadata`、`score.vector`）只用于兼容。
9. `/context` 必须只读，不得写 memory。
10. Trace Grader 只能读取 `events.jsonl`，不得修改 run archive 状态。

## 6. Known Limitations

- Trace Grader v0 检查 tool calls、write signals、validation commands、fake success claims，但不能判断任务语义质量。
- Eval runner 还没有自动接入真实 `events.jsonl` artifacts。
- Turn Intake 尚未实现；TaskLedger 目前需要显式写入。
- Doc Findings 已有类型与 recall 支持，但没有正式 write flow。
- Artifact Store 和 drill-down channel 尚未完成。
- Semble 是未来 Code RAG 集成点，不是 v0.4 blocker。
