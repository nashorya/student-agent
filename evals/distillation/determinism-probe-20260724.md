- 三条流确实同时运行并累计完成 32 个 HTTP 200 响应；没有 429、非 200

## 结论三：v0.3 主指标建议

用独立两组、`n=3/格` 的粗略正态近似，
`MDE ≈ (1.96 + 0.84) × CV × sqrt(2/3) ≈ 2.29 × CV`。这不是显著性
承诺，只是预算量级尺：

| 指标 | 串行 CV | n=3/格 粗估可分辨相对差 |
|---|---:|---:|
| 等价成本 | 0.089 | 约 20% |
| 未缓存 prompt | 0.108 | 约 25% |
| completion | 0.212 | 约 49% |
| Hashline / 阶梯 / tool_error | 0.247–0.250 | 约 57% |
| reasoning | 0.282 | 约 64% |
| 工具调用 / total tokens / 轮次 | 0.308–0.330 | 约 70%–76% |
| prompt / 缓存 prompt | 0.360–0.404 | 约 82%–92% |

定位轮次虽然样本 CV=0，但三次都固定为第 2 轮，是本题的天花板/离散退化，
不能据此宣称 MDE=0。

**建议不是一个裸效率数，而是两阶段主判据：**

1. 先以官方 harness `resolved=true` 作资格门；未 resolved 不进入“更省”
   比较，避免空 patch 因便宜而被奖励。
2. 在 resolved run 内，以**同题配对的等价成本中位数**作主效率指标；
   阶梯触发保留为机制副指标，不再单独用“少 30%”作稳定主结论。

理由：成本是本次最低的非退化 CV，但两个空 patch 同样便宜，必须受
resolved 门约束。阶梯 CV=0.25 时，`n=3/格` 粗估只能分辨约 57% 差异；
若坚持 30% 阈值，按独立组近似需约 **11 次/格**，或改用能实测配对相关性
并降低方差的同题配对设计。当前探针没有 harness，也没有完整并发组，所以
conditional-on-resolved 的成本 CV 与配对相关性仍未知，作者冻结 v0.3
数字前必须保留这一证据边界。
